# Overall and coupled pelvic recruitment

Wolverine's authoritative prepared shape and active final UnifiedCollar remain
the reference. Overall UI is 1..100, neutral 50; its source shape parameter is
.85..1.2..2.5, with the source's two centered linear branches. The verified
Win32 surface Session evaluates the complete anatomy and both coupled body
sections at state 2/all other controls 50. `export_overall_bank.py` records
topology, mechanics, source revision and hashes together. No game is modified.

The canonical source's prepared_shape.h, unified_collar_solver.h,
anatomy_surface.h and d3d9_proxy.cpp were rechecked against the imported snapshot:
all four are byte-identical. The final solver's radius-dependent asymmetric
recruitment and hard original-edge donor constraints govern this work; the
older isolated ramp is insufficient.

For another character, the complete evaluated source body displacement is
sampled in its explicitly calibrated source authoring frame. `SourceBodyField`
retains eight source point donors and weights per target body sample. This is
a material-field transfer across different character topology, not identical
Wolverine body vertices or full posed-body parity. Attachment lineage uses its
existing sparse original-source interpolation matrix.

`GraftCollar.solve_recruited` reconciles those prepared displacements through
the final source-derived screened cotangent/biharmonic metric and hard original
edge elimination. Fixed exterior rows receive their prepared displacement;
native waist/ankle boundaries receive zero. Solving displacement rather than
absolute geometry preserves the approved fitted neutral exactly and lets the
distal prepared surface grow outside the recruited pelvic region. UV aliases
and both seam halves share the resulting displacement.

A native adapter may blend baked resources sharing topology, material layout,
UVs, skin weights and inverse binds. Its dynamic guide and collision envelope
must track the same size state. `VirtualBindTranslation` supplies the translation
for a changed material pivot with an unchanged engine rig bind:
`current-material + offset-R*offset`, where `offset=material-bind`.
This produces `R*(vertex-material)+current` without moving vertex buffers on CPU.

Witcher owns its native morph components, menu, calibrated Geralt resources,
WitcherScript state changes and cook/install. Shared recruitment transfer and
pivot math remain in Base. Wolverine can adopt these portability helpers only
after its own comparison; its current source solver remains authoritative.
Future spokes pin the same contract, preserve native part boundaries and verify
native interpolation, moving seams, collision and frame cost separately.

Offline bakes and native cooking are not gameplay proof. A linear resource blend
between sampled source states is an approximation to nonlinear intermediate
source evaluation; record the measured interpolation error and supported keys.
