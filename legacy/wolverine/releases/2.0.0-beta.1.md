# Wolverine Anatomy Tool 2.0 Beta 1

Complete prerelease package for clean installation or upgrade from the exact approved 1.9 game assets. No prior mod download is required.

## Install and rollback

Close Wolverine, extract the entire WolverineAnatomyTool-v2.0.0-beta.1-Install.7z archive with 7-Zip, and run Install.cmd or Upgrade-Beta-2.0.cmd. For a different game location, run Install.ps1 -GamePath 'D:\Your Game Folder' from PowerShell. The installer verifies every payload file and accepts supported stock or already-patched Natural, WGame and WStart packages. Unsupported package modifications are rejected before any installation writes.

Replaced files are backed up under WGame/ModBackups/WolverineAnatomyTool-v2.0.0-beta.1. Run Rollback-Beta-2.0.cmd or Uninstall.cmd to restore the preceding files. Existing WolverineLive.ini, TeachingFluid.ini, TeachingAudio and camera settings are preserved. The 22 public default idle clips are included; replaced default clips are backed up. Camera settings remain after rollback. Close the game for installation and rollback.

F6 opens controls; J starts/cancels the teaching sequence. This beta includes the current DLL, all three WBX game patches, full-resolution DDS skin textures, menu PNG blends, shared normal/specular maps, default audio, fluid/camera defaults, installer, installer regression tools, manifest and checksums. Development source and authoring fixtures are a separate optional Source ZIP and are also available in the repository. No full game packages or private recordings are distributed.

## Changes

- Reduce the final anatomy render/fluid collision skin from 61,378 to **35,000 triangles** (43% fewer), and supporting triangles from 53,444 to 32,000. Deformation bindings, collider references, safety metadata and collar welds are remapped together, with no full-resolution anatomy fallback or runtime decimator.
- Retain the earlier surface and worker-pool optimizations; prune unused smoothing metadata and the disabled clinical pipeline.
- Correct the joined collar's lighting-normal winding.
- Strengthen upright support through existing angular inertia, spring and damping parameters.
- Cover the rendered shaft's ventral bulge with the existing contact envelope and tighten contact compliance, addressing reproduced post-movement shaft/scrotum overlap. Physics still uses the established 240 Hz step and 24 constraint iterations.

## Validation and limits

The reduction was checked across 48 static settings, 270 motion frames, 480 pulse frames and 88 saved poses. Minimum silhouette overlap was 99.15%; retained UV/skin-weight data and physics trajectories matched the pre-reduction baseline. Weld, sequence/hitch, collision/BVH/anchor and fluid-budget regressions passed.

On the final support/contact build, six overturn cases had no inverted settled samples and 18 perched/launch cases passed. In an actual post-movement floppy mesh capture, 21 shaft faces intersected the scrotal body before the contact fix and zero did afterward. All three tested modes now had zero such crossings; shared root/neck and coplanar contacts were excluded. These fixtures do not cover every live character pose or control combination.

The geometry-reduction benchmark measured **16–17% less CPU surface time** against the already optimized baseline. These are offline surface-stage timings before the final support/contact tuning, not whole-game FPS or a performance guarantee. Active-contact work can change as the corrected envelope engages.

**Known issue:** discoloration at the base was reported. The identified collar normal-winding error was repaired and checked against 88 posed geometries, but the subsequent user report was not resolved through confirmed live visual testing. Treat appearance and other untested live-scene behavior as beta limitations. A few near-degenerate facet differences are recorded in the geometry audit.

Runtime source and detailed audits remain available in the beta tag; revised packaging source is on main and in the optional Source ZIP. See [the full local snapshot notes](2026-09-29-compact-runtime.md) for additional measurements and limits.
